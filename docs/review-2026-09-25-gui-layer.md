# GUI-layer review, 2026-09-25

Read-only review of the layout tree and agent surfaces in five slices. Every high or critical finding was checked by an independent adversarial verifier; severities marked (verified) are the verifier's. Ids are `<slice>-<id>`: RL Rust layout, RS Rust surface, SK Swift kit, PH PublicationManagerCore host, AC agent-facing contract. Several findings were reported by more than one slice (e.g. RS-S1 = SK-K1 = AC-F1); [plan-wave-7-trusted-layer.md](plan-wave-7-trusted-layer.md) groups them.

## RL: rust-layout

- **RL-L1** (high (verified)) `crates/impress-layout-service/src/session.rs:299 (SessionRegistry::with) and crates/impress-layout-service/src/service.rs:614-656 (apply_verb), 1904 (instance = DefaultLayoutService::new)`: A cached LayoutSession is never checked against the stored row. Any long-lived process holding a session applies its next verb to a stale tree and writes it back with save_live, silently overwriting whatever the GUI (or another agent) did in the meantime. impress-mcp is exactly that process: every MCP call builds DefaultLayoutService::new(), which uses SessionRegistry::shared(), and nothing in impress-mcp ever forgets a session. The last write wins with no conflict signal. The GUI's feed then sees the external write, forgets its own session and redraws the agent's stale tree, so the user's split or close is undone in front of them. *Fix:* Add optimistic concurrency at the store boundary. Keep the row's `modified` timestamp (or a monotonically increasing `revision` payload field) on LayoutSession. In `with`, compare it with the row before running the closure (a cheap `get(item_id)`). If the row moved, reload the session and drop its rings, which is the honest outcome. save_live should compare-and-swap on it. Add a test in which two DefaultLayoutService instances, each with its own registry on one store, interleave verbs and neither loses the other's change. Exposing `revision` in LayoutResult and accepting an optional `expected_revision` on verbs is a later, ask-first step.
- **RL-L2** (high (verified)) `crates/impress-store-ffi/src/layout.rs:1117-1143`: The cross-process poll treats every `impress/ui/layout@1.0.0` row written by another connection as this window's tree. It does not check app_id, device or item id. All five chassis apps open one SQLite file (SharedWorkspace.databaseURL), and every verb writes the live row, including focus keystrokes, row selects and splitter releases. So a single h or l keystroke in impress makes every other running chassis app call forget_session, which drops both undo rings, bump its version and reload its whole tree and panes about 250 ms later. Saving a named layout from the CLI has the same effect everywhere. *Fix:* Match the mutation's item id against this scope's live row id (LayoutSession.item_id, exposed via the service), or read app_id and device from the row that ExternalPoll already loaded. Only then forget the session and bump the version. A named-layout row should refresh the Layouts menu (a separate `layouts_changed` signal or version class), not the tree. Add an FFI test: an external write to another app's live row must not call layout_changed and must keep the undo rings.
- **RL-L3** (medium (verified) **contract**) `crates/impress-layout-service/src/dto.rs:35-100 (PaneRefDto::to_pane_ref); crates/impress-service-macros/src/lib.rs:433-442 (args struct); crates/impress-pane-query/src/lib.rs:228-244 (PaneQuery)`: Agent-facing arguments are parsed permissively, and a typo falls back to the most dangerous default. PaneRefDto ignores unknown keys, and an empty reference means 'the focused pane'. Two spellings of a pane reference also exist: Verb/PaneRef, as the FFI, HTTP and the `patch.verb` echoed in every result use it, is `{"ref":"id","tile":7}`, while MCP/CLI PaneRefDto is `{"id":7}`. An agent that copies a reference from a result into `layout-service_close` gets `{ref, tile}` read as `{}`, and the FOCUSED pane is closed with ok:true. PaneQuery has the same problem: `{"kind":"publication"}` (singular) deserializes to empty kinds, which compile to every kind in the manifest, and a misspelled `filter` is dropped. The result is a silent broadening rather than a refusal. *Fix:* On the argument path only (the macro's args struct, PaneRefDto, and the PaneQuery/PaneSpec received as verb arguments), refuse unknown fields and refuse a PaneRefDto that sets more than one selector. Require `focused: true` to be explicit, or accept `{}` only with a documented warning in `message`. Also accept the Verb spelling `{"ref":"id","tile":N}` in PaneRefDto so the round trip works. Leave persisted Layout rows lenient. This makes the wire stricter, so it is ask-first.
- **RL-L4** (high (verified)) `crates/impress-layout/src/patch.rs:174-219 (restore); crates/impress-layout/src/undo.rs:214 (undo_exploration)`: Per-pane exploration rings and the arrangement ring replay whole-value diffs out of order, with no conflict check and no normalize. A Select patch stores the ENTIRE ChannelState, so undoing pane A's selection also wipes a selection that pane B published later on another channel. A SetQuery patch stores the pane's whole PaneSpec, including role, channel and session. Suppose SetRole(Q, list) later took `list` from P on the arrangement ring. Undoing P's earlier SetQuery restores P's old spec with role `list`, and two panes now hold one role. That breaks the D5 uniqueness invariant, and ⌘0 and ⌃⌘S become a coin toss. The property tests only check revert immediately after apply, so none of this is pinned. *Fix:* Before reverting or reapplying, verify that every entry the patch touches still equals its `after` (or `before` for redo). If one does not, refuse with 'pane N changed since; nothing undone' and drop that ring entry. Make Select patches record only the (channel, kind) entry they published, not the whole ChannelState. Run normalize plus the invariant checks after a step. Add a seeded property test that interleaves verbs across rings with random undo/redo and asserts assert_arena_is_sound, role uniqueness and no cross-pane effect.
- **RL-L5** (medium (verified) **contract**) `crates/impress-layout/src/layout.rs:175-184 (current_window)`: 'Current window' is defined as the first window with a focused leaf. normalize guarantees that every window has one (layout.rs:756-759), so current_window is always windows[0]. After Detach (D4's detached PDF), every Focused, Role and Direction reference and every verb the service resolves goes to the FIRST window, even though do_detach says 'Focus follows the pane'. snapshot.focused/leaves and the undo exploration target also read window 0. h/l, ⌘0 and a bare 'close' from the detached window therefore act on the main window. *Fix:* Make the key window a first-class value: `Layout.current: Option<WindowId>`, set by focus_tile, detach and split, and repaired by normalize. Alternatively, give every verb an optional `window` argument that the host fills from the key NSWindow. Add a test: detach, then `close {focused}`, closes the detached pane. Either way the Layout shape or verb arguments change, so this is ask-first.
- **RL-L6** (medium (verified)) `crates/impress-store-ffi/src/layout.rs:1211-1216 (build_subscriptions), 1117-1143; crates/impress-store-ffi/src/ui_feed.rs:106-137; the whole of crates/impress-layout-service/src`: The Rust half of the layer does no logging at all: no `log::` or `tracing::` in impress-layout, impress-layout-service, impress-pane-query, layout.rs or ui_feed.rs. A verb that the service refuses, a cold start, a session reload or forget, an external-write detection, a spurious version bump and a subscription rebuild all leave no trace. Worse, failures are swallowed. If build_subscriptions cannot read the layout, it returns an empty registry and no pane is invalidated again until the next version bump. ExternalPoll turns a data_version or query error into 'nothing changed'. The session log's unexplained 'layout changed elsewhere' lines (plan-wave-6 line 365) had to be diagnosed from Swift alone. *Fix:* Add `log` to impress-layout-service and impress-store-ffi and log under category `layout`, the facade the surface runtime already bridges. Log one line per applied or refused verb (actor, verb, target, version, message), each cold start, session load, forget and external detection (with the row id and app), and every swallowed error, at warn level. The feed should never return an empty subscription set silently.
- **RL-L7** (medium) `crates/impress-store-ffi/src/ui_feed.rs:106-137 (ExternalPoll::check); crates/impress-core/src/sqlite_store.rs:5240`: The cross-process path can lose writes for good. (1) `last_data_version` is advanced BEFORE the rows are read, so a failed items_modified_since drops that change forever. (2) The cursor is `modified > high_water_mark`, where `modified` is the writer's wall-clock time when it built the item, not commit time. A write built before another row's timestamp but committed after it (for example impress-mcp waiting on the write lock during an import) is never seen, and neither is a second write in the same millisecond. (3) Hard deletes, such as `delete_layout` from the CLI, never appear, so the Layouts menu stays stale. *Fix:* Advance data_version only after a successful read. Query with an overlap window (`modified > hwm - slack`) and dedupe by (id, modified), or better, key the cursor on a commit-ordered column such as rowid or a change-sequence table. Report deletes by diffing the set of ids under the prefix when data_version moves, or record a tombstone. Test with two connections that write out of timestamp order.
- **RL-L8** (medium) `crates/impress-layout/src/undo.rs:221-228 (forget_closed_panes); crates/impress-layout/src/patch.rs:201-206 (next_tile restore)`: Exploration rings are never pruned outside tests. The doc says 'The service calls this after a close', but no service code calls it. Undoing a split also restores the `next_tile` allocator, so the next split hands out the SAME TileId again. That new pane inherits the dead pane's exploration ring, and ⌘Z in it restores the old pane's spec over the new one. *Fix:* Never roll the allocator back: exclude next_tile/next_window from revert, since ids are documented as never reused. Also drop the rings of panes that no longer exist after every applied verb and undo step (LayoutSession::apply/undo). Add a test: split, explore in the new pane, undo the split, split again, then undo in the new pane is a no-op.
- **RL-L9** (medium) `crates/impress-store-ffi/src/layout.rs:1151-1163 and 747-765 (finish)`: The feed works out whether a tree change came from this object by comparing the registry generation with a version counter sampled on its own 10 ms tick. The service bumps the generation inside the lock, and `finish` bumps the version afterwards. If the feed ticks in between, it adds a spurious version bump. If a surface effect and a local verb land in the same tick, the surface change is taken for the local verb and never reported, whenever `finish` had already re-read the tree. `finish` also bumps the version for verbs that changed nothing (an empty-ring undo, a focus on the focused pane). *Fix:* Have LayoutVerbResult (or the session) return the generation the verb produced. `finish` records it as 'generations I caused', and the feed reports every other generation. Skip the version bump when the patch is empty.
- **RL-L10** (medium) `crates/impress-store-ffi/src/lib.rs:823,851 (layout_sessions: Arc::new(SessionRegistry::new())); crates/impress-layout-service/src/service.rs:603-607, 1904`: One app process ends up with two session registries for the same scope. SharedLayout and the surface executor share SharedStore.layout_sessions, but any in-process inventory call of a layout-service method builds DefaultLayoutService::new(), which falls back to SessionRegistry::shared(). The kit is force-linked into the app for precisely this dispatch. Both registries write through the same installed connection, so data_version never moves and neither registry learns about the other. The window and the inventory path then diverge and overwrite each other. *Fix:* Install the SharedStore's registry as the process-shared one, mirroring install_store (for example `SessionRegistry::install(arc)`), so that `shared()` and `layout_sessions()` return the same Arc. Or make SharedStore use `SessionRegistry::shared()`. Add an FFI test: a verb made through `impress_capabilities_kit::call("layout-service_split", ...)` shows up in SharedLayout.snapshot and fires layout_changed.
- **RL-L11** (medium **contract**) `crates/impress-layout-service/src/dto.rs (LayoutVerbResult ok/message); crates/impress-store-ffi/src/layout.rs:143-146 (SharedLayoutError::Layout{message}); crates/impress-layout/src/apply.rs:519-522, 324-328`: Refusals reach every caller only as prose. LayoutError is already a serde-tagged enum (`unknown-tile`, `no-pane-with-role`, ...), but the service calls `e.to_string()`, and the FFI puts every refusal into one `Layout{message}` case. So neither an agent nor Swift can branch on 'no such pane' versus 'last pane' without matching text. Messages also do not say which verb or argument failed. Some are wrong: Detach of a whole window and MoveTile of a window root return CannotCloseLastPane, whose text is 'a window must keep at least one pane'. *Fix:* Add an optional `error: Option<LayoutError>` (or a stable `code` string) next to `message` in LayoutVerbResult/PaneResult, and `code` on SharedLayoutError::Layout. Prefix messages with the verb and the resolved target. Add `AlreadyItsOwnWindow` and `CannotMoveWholeWindow` variants. The result shape and the error enum both change, so this is ask-first.
- **RL-L12** (medium **contract**) `crates/impress-layout-service/src/dto.rs:559-565 (view_kind); crates/impress-layout/src/ids.rs:204-216; service.rs set_query/select/split`: Verbs accept values that can never render and return ok:true. `view_kind()` rejects only the empty string, and its hint names 'editor', which is not a view kind (the session-bearing kind is `source`). Rust's ViewKindId constants lack notes, bibtex and surface, which exist only in Swift's ViewKindRegistry. So the 'one closed vocabulary' is split across two languages with no test pinning the two lists. set_query, set_pane and split do not compile the query, and select does not check `kind` against the manifest. The agent learns of a mistake only when a later get_pane returns a refusal, or never, for a selection of kind 'publications'. *Fix:* Keep the view-kind table in Rust (constants plus a `KNOWN` list), export it over FFI as kind_manifest_json already is, and pin Swift's registry to it in a test. At verb time, compile the new query against the manifest and check Select's kind. Either refuse, or return ok with a `warnings` list ('pane 3 will render a placeholder: unknown view kind'). Refusing is ask-first; warnings are additive.
- **RL-L13** (medium **contract**) `crates/impress-store-ffi/src/layout.rs:545-579 (resize_share); packages/ImpressLayout/Sources/ImpressLayout/LayoutController.swift:489-507 (toggleRole); crates/impress-layout/src/shares.rs (HIDDEN_SHARE / is_hidden)`: Collapsing a role, the ⌃⌘S chord, is decided outside the verb vocabulary. The FFI reads the tree outside the session lock, rebuilds the whole shares vector (filling missing entries with 1.0 and clamping to HIDDEN_SHARE) and sends a Resize. That is a TOCTOU: a concurrent verb produces a confusing 'N shares for M children'. Swift decides whether to hide or restore, and restores to the SIBLING AVERAGE, so hiding and showing a 240 pt sidebar gives it the average width of list and detail. MCP and CLI have no equivalent of the gesture. 'Hidden' is an absolute float threshold (≤1e-3) on relative weights, so it is not a stated fact in the tree. *Fix:* Add one verb, `set-collapsed {target, collapsed}` or `resize-share {target, share}`, applied inside the session lock. The tree keeps the pre-collapse share (for example `collapsed: Option<f32>` on the Linear slot), so restoring is exact and undo, sync and applyLayout keep it. Swift then only maps the chord. This adds a verb and a tree field, so it is ask-first.
- **RL-L14** (medium) `crates/impress-layout-service/src/service.rs:1420-1445 (get_pane), 1848 (CollectionSubtrees); crates/impress-store-ffi/src/layout.rs:424-437 (run_pane), 747-765 (finish), 1241 (CollectionSubtrees copy); crates/impress-layout-service/src/store.rs:151-200 (save_live/live_row)`: The hot paths do redundant store work while holding the process-wide registry mutex. That mutex covers every scope and the surface executor, and the GUI calls these methods synchronously. Each get_pane, which run_pane calls on every display pass, runs four `collection_ops::list_tree` scans inside the lock. run_pane then serializes the compiled query to JSON and parses it straight back. Every verb, keystroke focus included, runs save_live: it queries ALL layout rows, deserializes the old tree only to discard it, and writes an attributed operation row. That write is what triggers L2 in every other app. `finish` then takes the lock again for get_layout, clones the tree and serializes it. The CollectionSubtrees resolver is duplicated verbatim between the service and the FFI. *Fix:* Make the service's CollectionSubtrees public and delete the copy. Build it outside the lock, or cache it keyed on data_version plus collection mutations. Give the FFI an internal `compiled_pane(tile) -> CompiledQuery` so run_pane skips the JSON round trip. Keep the live row id on the session so save_live patches it directly. Skip save_live for patches that touch only `windows[].focused` (or coalesce them). Return the tree from the verb result instead of re-reading it.
- **RL-L15** (medium **contract**) `crates/impress-layout-service/src/service.rs:1393-1400 (get_layout), 1426, 1475, 1532`: The read verbs hard-code ActorKind::Agent. A read that finds no row cold-starts and writes it, and a first touch that adds sessions saves again. The GUI's first SharedLayout.snapshot() at launch therefore records the user's workspace row as 'agent:layout-service'. with_session's own doc calls exactly this worse than the alternative. *Fix:* Give get_layout, get_pane, get_channel and resolve_reference an optional `actor` (defaulting to agent, as the verbs do). In the FFI, pass `human` from snapshot, pane and run_pane. The argument is additive but changes MCP shapes, so it is ask-first.
- **RL-L16** (medium) `crates/impress-layout-service/src/presets.rs:270-288 (previous_revision), 1128-1154 (upgrade_if_untouched)`: The preset-upgrade mechanism is a one-off workaround shaped like a general one. previous_revision rebuilds revision N-1 by swapping q::inbox() for q::inbox_revision_1() and labelling it SHIPPED_VERSION - 1. As soon as revision 3 ships for any other reason, 'previous' is computed wrongly, untouched revision-2 rows are treated as user-edited and never upgraded, and no log explains it. A row two revisions behind is also never upgraded. *Fix:* Keep a table of fingerprints (a hash of the canonical stored form) for every shipped revision of every preset, generated by a test that fails when a preset changes without a new entry. Upgrade when the row matches ANY shipped fingerprint. Log (under `layout`) when a row is left alone because it differs from them all.
- **RL-L17** (medium) `crates/impress-layout-service/src/store.rs:178-200 (live_row), 567-573 (layout_of)`: A live row that no longer decodes permanently bricks its scope. Causes include a hand edit, a sync merge, or a future Tile or Verb rename. load_live returns the error, so every snapshot, verb and read fails with 'read layout tree: ...'. Nothing falls back to the cold-start preset, keeps the bad row aside or tells the user what to do. The placeholder mechanism exists for unknown view kinds but not for an undecodable tree. *Fix:* On a decode failure, log at error level with the row id and serde path, and mark the row `is_live: false` with a `quarantined_reason` (or rename it to a named layout 'Unreadable layout <date>'). Then cold-start a fresh live row and report it in the message, as for a missing row. Add a test with a corrupt payload.
- **RL-L18** (low **contract**) `crates/impress-layout-service/src/lib.rs:112-121 (skipped), report.rs:19-24, 68-71`: When the app is not listening, Tier B reports every capability as `pass: true, skipped: true`, and `report.ok()` is true. An agent or CI step that reads `ok` or `pass` sees green after zero checks, which contradicts the comment that 'A skip is not a pass: it says so'. Tier::B's doc is also stale: 'The layout tree has no live-app surface yet (that is L5/L6)'. *Fix:* Set `pass: false` on skips (the counts already exclude them) and add `ran_any()` or an `all_skipped` flag. Make the CLI print 'SKIPPED: app not reachable on <url>' distinctly, and fix the Tier::B doc. Changing the meaning of `pass` is a small report-shape change, so it is ask-first.
- **RL-L19** (low) `crates/impress-layout/src/layout.rs:540-544 (pane_with_role) vs 391-395 (resolve Role); apply.rs SetRole`: Roles are scoped three different ways. SetRole enforces uniqueness per window, and PaneRef::Role resolves in the current window only. Layout::pane_with_role, which backs FFI pane_with_role and therefore Swift's toggleRole, scans every window in tile-id order. With a detached window holding its own `detail`, ⌘0 can collapse a pane in the wrong window. *Fix:* Make pane_with_role take a WindowId, and use the FFI's current or key window (see L5). Or document roles as layout-global and enforce that in SetRole. Pin the choice with a test.
- **RL-L20** (low **contract**) `crates/impress-store-ffi/src/layout.rs:450-475 (apply), 944-966 (bare_split); crates/impress-layout/src/verb.rs:114-120`: Split has two shapes. Verb::Split requires `new`, while the service's `split` takes `new_pane: Option`. The FFI bridges them by parsing the JSON a second time as a Value and guessing. Only on that path does a missing `target` default to Focused, and the original serde error is reported only when the guess also fails. So the FFI and HTTP contract for split lives in no type. *Fix:* Make `Verb::Split.new` an `Option<PaneSpec>` with `#[serde(default)]`, resolved in LayoutSession by duplicating the target, the rule the service already applies, and delete bare_split. The Verb schema changes, so this is ask-first.
- **RL-L21** (low) `crates/impress-store-ffi/src/layout.rs:931, 1340-1352; crates/impress-layout-service/src/dto.rs:156-171`: Several small silent successes. snapshot_of, kind_manifest_json and cold_start_layout_json turn a serialization failure into "{}", which reads as an empty tree or manifest. geometry_json does `.ok()`. parse_channel says 'Use 1-8' but silently clamps 9-255 to 8, so an agent asking for channel 12 lands on 8. *Fix:* Make snapshot_of return Result, which the callers already do. Log and panic in debug builds for the manifest exports. Refuse channels above ChannelId::MAX with the existing message.
- **RL-L22** (low) `crates/impress-layout-service/src/session.rs:341-350; crates/impress-layout-service/src/store.rs:40-46`: Docs that are now wrong for someone building on the layer. `TODO(L4)` still describes forget as a temporary lever, but it became the permanent D6 mechanism (L2). store.rs's 'Startup guard' says nothing here may be called in the first ~90 s, yet the host's launch snapshot must cold-start and write here, and the real guard lives in the FFI feed's grace period. *Fix:* Rewrite both. State that forget is the cross-process refresh and what it costs (the rings), with a link to the fix in L1 and L2. - **RL-L23** (low) `crates/impress-pane-query/src/lib.rs:62-110 (EdgeType); crates/impress-core/src/reference.rs:78-100`: EdgeType is copied between the two crates, with a From impl in one direction only. A variant added to impress_core::EdgeType still compiles, but a pane query can never name it, and no test compares the two enums. *Fix:* Add the reverse exhaustive `From<impress_core::EdgeType> for impress_pane_query::EdgeType`, which turns a missing variant into a compile error, plus a serde round-trip test over every variant.
- **RL-L24** (low) `crates/impress-layout-service/src/service.rs:1320-1368 (delete_layout); crates/impress-layout-service/src/tier_b.rs:83, 397-426`: delete_layout ignores `actor` and hard-deletes the row with no attributed operation, so history cannot say who removed a saved layout. Tier B's restore point is saved with save_named, which is Durable and portable, so it can sync to other devices mid-run and takes a ⌃⌘ ordinal. Saving and applying it also resets the user's undo rings (commit_boundary/replace), and nothing reports that. *Fix:* Record deletes as an attributed operation (or a tombstone) at Durable tier. ## RS: rust-surface

- **RS-S1** (high (verified)) `crates/impress-store-ffi/src/surface.rs:349 (per-handle SessionRegistry), :801-853 (SurfaceFeed.run); crates/impress-surface-service/src/runtime.rs:959-986 (SessionRegistry::with)`: A surface runtime, once loaded, is never reloaded from the store. `with` reads the spec and state only when the key is missing. Every SharedSurface keeps its own registry, and the feed only tells Swift that something changed; it never drops the cached runtime. The layout tree hit the same bug and fixed it with `forget_session`; surfaces never got that fix. As a result: (a) a `surface_update` sent over MCP from a chat keeps rendering the OLD spec in the app pane until the pane is reopened; (b) an HTTP dispatch or `surface_state_set` writes state through a different handle (the HTTP bridge opens a fresh `SharedSurface` per request), and the pane then re-renders its stale in-memory state; (c) the next human click in the pane persists that stale state over the agent's write, so the update is lost. Separately, `with`'s take-out-and-put-back pattern means two concurrent calls on one key overwrite each other. Its doc comment says this would be 'revisited in S6/S7'; it was not. *Fix:* Make `SharedStore` own ONE surface `SessionRegistry` (as it already owns `layout_sessions`) and have every SharedSurface handle, including the HTTP bridge's, use it. In SurfaceFeed, call `registry.forget_surface(id)` before notifying, for any mutation this registry did not write. Alternatively, keep a write generation or the row's `modified` time on SurfaceRuntime and reload in `with` when the stored row is newer. Add a Tier-A/FFI test: update the spec via a second handle, render on the first, expect the new spec.
- **RS-S2** (high (verified)) `crates/impress-surface/src/plan.rs:124-145; crates/impress-surface-service/src/runtime.rs:608-672`: Query and verb sources are never re-run when the store changes. ADR-0033 Defaults promise re-runs 'when a store invalidation names a query'. In practice a query source's hash is only query+params, and params are always `{}` (see S3), so it is fetched once per runtime lifetime. The pane's runtime lives for the whole app session (S1), and the surface feed only watches `impress/ui/surface*` rows. So a paper-triage table goes stale as soon as the user stars or reads a paper anywhere else; only an explicit `refresh` action repairs it. *Fix:* Add `SurfaceRuntime::invalidate_sources(kinds)`, which drops cache entries for query sources whose compiled kinds intersect the mutated schema refs (verb sources could opt in, or use a TTL). Have the FFI feed also watch non-UI mutations for kinds any live runtime queries, then call it before notifying. Pin this with a Tier-A test: seed a publication, render, star it through the store, re-render, expect a changed row.
- **RS-S3** (medium (verified) **contract**) `crates/impress-surface-service/src/runtime.rs:575-580, 597, 866-878, 297-309`: The `param` root and pane parameter bindings do nothing. `SurfaceRuntime.params` is always `{}`, and no verb, FFI method or HTTP route sets it. `bindings_from_params` therefore always returns empty, so a query source with `$param` compiles to an empty set. `run_query` passes `decls = &[]`, so a required parameter is never flagged either. Meanwhile `validate` accepts `{{param.selected}}` (probe: `validate` returns `[]`), and the reference renders as a placeholder every time. ADR-0033 D1 ('the same surface in three panes with three different parameter bindings') and the documented `params` block in both worked examples depend on this. *Fix:* Resolve the pane's parameters from the layout (its PaneSpec params and channel values, where `pane_showing` already reads) inside render/dispatch, or have the FFI `render`/`dispatch` take a `params_json`. Pass `spec.params` as decls to `compile`, so an unbound required parameter becomes a source error. Have `validate` check `param.<name>` against `spec.params`.

## Strengths to keep

### RL
- Layout::apply_in runs every verb on a scratch clone, then normalizes, then diffs. A refused verb leaves the tree byte-identical, and the patch is computed rather than predicted. The seeded-LCG property test (400 seeds x 24 steps, >5000 applied verbs) pins the arena, focus, normalize fixed-point and apply/revert/reapply invariants.
- There is one closed Verb vocabulary, and the FFI dispatch is a pure translation table onto layout-service methods. The inventory test spells out all 35 MCP tool names instead of deriving them, so a dropped #[impress_method] fails CI.
- LayoutError is a typed, serde-tagged enum with clear messages, and the pane-query crate keeps 'wrong' (a typed PaneQueryError) apart from 'unfilled' (a query that matches nothing). This is the right foundation for machine-readable refusals once it reaches the wire (L11).
- The FFI feed does debouncing, burst capping and the 90 s startup grace at the source, and it is covered by real tests (external connection writes, external tree writes, cross-object verbs). The CLAUDE.md render-loop guard lives in one place rather than in every subscriber.
- The module docs record WHY, including live evidence with dates (the forget_session and generation rationale, retention tiers, ordinal stability by creation, the newest live row winning). Store invariants are enforced in code: one live row per scope, and field names spelled once in `field::`.

### RS
- Pure plan/resolve/reduce with no I/O makes a surface fully headless and inspectable. surface_render returns exactly what the human sees, goldens pin the RenderTree wire shape, and reduce_properties.rs pins 'a set never drops sibling keys'. Keep this split and extend it rather than growing logic in the runtime or in Swift.
- Placeholder-with-reason degradation: one bad reference or failed source never blanks the surface, and since W1(b) the placeholder names the failed source and why (resolve_with_source_errors, tests/source_errors.rs). This is the right error model to extend (S7, S11, S12).
- EffectOutcomeDto separates 'done' from 'nobody was listening' per effect. publish/open reported 'no pane shows this surface yet' instead of pretending success, and the pane_showing lookup was a principled fix grounded in the layout tree as the one source of truth.
- impel-tools refuses (AppUnavailable) instead of silently falling back to SQLite, re-probes with a cooldown, and serializes its global-state tests. HostAdapter reads the verb-host slot fresh on every call, so a late install works, and both behaviours are pinned by tests.
- validate never panics and names every problem by path. The store module spells every payload field once (`field::…`), deletes cascade to state and event rows, and the event ring is bounded, all following the schema-ref discipline in CLAUDE.md.

### SK
- LayoutModel/RenderTree are strictly decode-only mirrors. They use explicit CodingKeys (no key strategy that would rewrite the opaque `query`/`view_state`), and both are pinned against the Rust goldens (three_column.json, signal-explorer.render.json), so a serde change fails a test instead of blanking a window.
- All layout mutations go through `LayoutController.apply`/`perform`: tree verbs are forwarded as JSON, with actor attribution (human vs agent) and the three-point trace (request / version+affected / display). The HTTP seam uses the same code path and answers 409 when no host is registered and 422 when Rust refuses a verb.
- `LayoutController.isNewer` states its reasoning, grounded in the Rust feed's monotonic AtomicU64 (including the external-write bump in layout.rs), and pins it with the exact live regression (101→103 then 101, 102 delivered).
- The surface route table is Rust's (`SharedSurface.surfaceHttp`) and ImpressAutomation forwards verbs verbatim, so a new Rust verb or route reaches HTTP with no Swift change and the vocabulary exists in one place.
- Unknown view kinds degrade to a placeholder that keeps the pane's spec (`resolvedKind(for:)` is a pure, tested lookup). The kit-demo proves the standalone cut. PaneSessionRegistry refuses to evict a pinned, on-screen session and separates flush from abandon for deletes, which prevents resurrecting a deleted record.

### PH
- Rust makes the decisions and the host only maps them. Outline routing (`outline_row_verbs_json`, `outline_cleared_verbs_json`, `initial_selection_applies`), section tables and session ids all come from Rust. LayoutOutlineNodeTests sends every tab shape through the real FFI instead of a Swift fixture, so a wire-form drift fails in `swift test`.
- The source pane's editor outlives its SwiftUI views without `.id`. `TypstEditorHost` (the NSTextView is moved between containers, never rebuilt; one UndoManager per manuscript; a history is cleared when the text changed while away; an external change is applied in place and the caret stays put) and `SourcePaneSession` in the kit's `PaneSessionRegistry` are well tested in SourcePaneEditorTests and were proven live across split, swap and preset change.
- The pane views reuse existing views instead of rewriting them. `info`, `pdf`, `notes`, `bibtex`, `plot` and the manuscript preview call the existing DetailView, PDFTab, NotesTab, BibTeXTab, FigureArtifactView and ManuscriptPreviewContent. Row menus and drag payloads are the one definition the legacy lists use. There is no second copy of a capability to drift.
- Observability is designed for agents. Each pane logs one line saying what it is showing (`pane N info: publication detail for <id>`, `pane N plot: … (no rendered artifact)`, `outline select … → legacy, reason`). Empty states say what was asked for and why it cannot be shown ('Detail Unavailable' naming the kind, 'Query Refused' versus 'Nothing Here'). The outline's mutation and save steps are logged.
- The host plugs into the kit through a small seam. `ChassisViewKinds.registerIfNeeded()` runs in `ChassisRootView.init`, before any pane, is idempotent and logs itself; `SurfaceHooks.chassis` and `LayoutHostServices` do the rest. The automation conformance forwards verb JSON unchanged to Rust (no third Swift copy of the Verb enum) and records the `agent` actor, so a script's verb and a keystroke take the same path.

### AC
- The route table for surfaces lives in Rust (`SharedSurface::surface_http`), and Swift passes method, path and body through without touching them. The 409 'no host registered' reply (versus 404) distinguishes 'this app cannot serve yet' from 'no such route'. Fixing F9 should keep this single-table design.
- `surface_validate` names each problem by JSON pointer and checks verb existence against both the linked inventory and the installed VerbHost, so a malformed spec comes back as a list of fixes (seen live: version, template ref, unknown kind, unknown verb in one answer).
- Failures are made visible in the data: `EffectOutcomeDto` per effect, `source_errors` on `surface_render`, and placeholders whose `reason` names the failing source ('source 'bad' failed: … expected f64'). This is the 'done vs nobody listening' discipline F11 and F18 should extend to `ok`/messages/logs.
- Pure plan/resolve/reduce behind `surface_render` makes every surface inspectable and testable headlessly. The Swift RenderTree decoder turns unknown kinds into placeholders instead of throwing, so older hosts survive newer specs.
- The inventory tests (`every_verb_reaches_the_mcp_inventory`, `every_verb_describes_itself_to_the_model`) keep the 15 surface verbs present and self-described. Layout verbs default `actor` to agent and name their undo ring (`stack`, `stack_pane`) in every result, which is the model surfaces should copy (F5).
