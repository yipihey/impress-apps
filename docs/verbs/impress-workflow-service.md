## `impress-workflow-service_workflow-create`

Store a spec as a new `impress/workflow@1.0.0` row, after validating it exactly as `workflow_validate` does — a spec with an error is refused (`invalid-spec`) and nothing is stored. **An agent caller's row is always `state: proposed`** (D-R6), whatever `spec.state` said; a person's row keeps the state the spec named.

- **safety**: `mutating`
- **reads**: "impress/workflow@1.0.0"
- **writes**: "impress/workflow@1.0.0"
- **reach**: —

| Argument | Type | Required | Description |
|---|---|---|---|
| `spec` | object | yes | The stored document (`impress/workflow@1.0.0`). |

**Examples**

- `manual macro`:

  ```json
  {"spec": {"wire_version": 1, "name": "example", "state": "proposed", "author": {"kind": "agent", "name": "example"}, "trigger": {"manual": {}}, "steps": []}}
  ```

## `impress-workflow-service_workflow-validate`
