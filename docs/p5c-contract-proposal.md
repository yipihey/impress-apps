# P5c retained-route contract decisions

**Authorized 2026-09-29.** Tom explicitly overrode the ask-first rule and
delegated the remaining contract decisions, including verb arguments, to this
session. The choices below are the implementation baseline. P5b's richer REST
behavior remains authoritative until each native contract and caller migration
passes parity checks. Existing descriptors use the generated form
`service-name_method-name`.

| App / retained route | Disposition and exact contract choice | Why / sequencing |
| --- | --- | --- |
| **imbib** — `GET /api/search`, `GET /api/papers/{citeKey}` | **Mixed composition and one additive query contract.** Extend `imbib-library-service_search-publications(query: String, limit: u32, offset: Option<u32>, filters: Option<PublicationSearchFilters>)`; filter fields are `read: Option<bool>`, `collection: Option<String>`, `library: Option<String>`, `tags: Option<Vec<String>>`, `flag: Option<String>`, `added_after: Option<String>`, and `added_before: Option<String>`. Hydrate every returned `PublicationSummary` with `imbib-library-service_get-publication-detail(id)` and map `PublicationDetailRecord.fields` into the REST paper shape. For exact cite-key lookup, use existing `imbib-search-service_find-by-cite-key(cite_key, library_id: None)`, then hydrate by ID. | Search summary is missing route fields and the route also supports filters/offset, so direct one-verb substitution is not parity. Exact lookup already exists; do not use fuzzy search for the key route. Move callers only after the hydrated/filter-equivalent response is demonstrated. |
| **imbib** — `GET /api/search/external` | **Additive DTO field:** add `identifier: Option<String>` to `ExternalPaper` returned by `imbib-app-service_search-sources(query, sources, limit)`, populated with the same importable identifier the HTTP candidate exposes, including candidates without DOI/arXiv/bibcode. | Search args already match; callers cannot safely reconstruct every candidate's import key from current fields. Migrate caller, prove identifier parity, then retire. |
| **imbib** — `POST /api/papers/add`, `/api/papers/resolve` | **Additive verbs:** add `imbib-library-service_import-identifiers(identifiers: Vec<String>, library_id: Option<String>, collection_id: Option<String>, download_pdfs: bool) -> IdentifierImportResult` with per-paper `added`, `duplicates`, and `failed` outcomes; and `imbib-app-service_resolve-citation(query: Option<String>, bibtex: Option<String>, citation: Option<CitationInput>, library_id: Option<String>, download_pdfs: bool) -> CitationResolution { via, paper?, candidates?, reason? }`. `CitationInput` carries `authors`, `title`, `year`, `journal`, `volume`, `pages`, `doi`, `arxiv`, `bibcode`, `raw_bibtex`, `free_text`, and `preferred_database`. | Existing `imbib-library-service_import-papers(papers, library_id)` only imports BibTeX and aggregates counts; `imbib-app-service_resolve-identifier(identifier, download_pdfs)` cannot accept the route's free-text, BibTeX, or structured citation forms and ranked candidates. Keep both routes until results preserve per-paper outcomes and the caller has moved. |
| **imbib** — `GET /api/libraries`, `GET /api/collections` | `imbib-library-service_list-libraries()` needs additive `collection_count` and `can_edit` fields. Keep existing `imbib-library-service_list-collections(library_id: String)` unchanged: call it once per library returned by `list-libraries`, then map the rows' `library_id` and library name. | Cross-library listing is caller composition; no optional argument is needed. Add only the missing library fields, migrate, then remove these routes. |
| **imbib** — `POST /api/collections` | **Caller-only composition.** Keep `imbib-library-service_create-collection(name, library_id, is_smart, query)`. If HTTP `libraryID` is absent, call `imbib-library-service_get-default-library()` and pass its ID; map HTTP `predicate` to `query`. | The existing verb covers smart/manual and predicate behavior. The HTTP handler itself resolves an omitted library to the default and errors when none exists. |
| **imbib** — `GET /api/collections/{id}/papers` | **Caller-only composition.** Use `imbib-library-service_list-collection-members(collection_id, sort_field, ascending, limit, offset)` and hydrate each row with `imbib-library-service_get-publication-detail(id)` to restore the HTTP paper shape. | Existing verb already pages members; verify HTTP default ordering and record conversion before deleting the arm. |
| **imbib** — `POST /api/collections/add-papers`, `PUT /api/collections/{id}/papers` | **Additive verb:** `imbib-library-service_update-collection-members(collection_id: String, identifiers: Vec<String>, action: String) -> CollectionMembershipResult { assigned: Vec<String>, not_found: Vec<String> }`, where action is `add` or `remove`. Resolve the same identifier forms as the HTTP handler and preserve per-item outcomes. | Existing `add-to-collection`/`remove-from-collection` take publication IDs and return only aggregate `MutationResult`; they cannot preserve arbitrary identifier resolution or the route's assigned/notFound lists. One shared mutation contract should serve both routes. |
| **imbib** — `DELETE /api/libraries/{id}`, `DELETE /api/libraries` | **Additive deletion contract:** add `delete_files: bool` to `imbib-library-service_delete-library-undoable(id, delete_files)` and add `imbib-library-service_delete-libraries(ids: Vec<String>, delete_files: bool) -> u32`. Preserve false as unlink-only; true removes shared and legacy library file containers; preflight every UUID and existing library before cleanup or store mutation; batch emits one consolidated mutation event. If cleanup fails partway, refuse and disclose partial file cleanup without deleting library rows. Store undo does not restore removed file bytes. | Existing service has single-library deletion only and no file option. The app's exact file-container cleanup must run in the native backend; headless calls may delete rows only when `delete_files` is false. |
| **imbib** — `GET /api/tags` | **Additive arguments/DTO:** extend `imbib-tags-service_list-tags-with-counts(prefix: Option<String>, limit: Option<u32>)`; add `id: String` and `parent_path: Option<String>` to `TagWithCount`. Set `id` to `path` because the store has no tag UUID; the current REST `TagResult` fabricates a new UUID on each read. | The existing verb already returns flat counts; the REST route adds filtering, a limit and hierarchy metadata. A stable path ID avoids preserving the route's random, nonpersistent identifier. |
| **imbib** — `GET /api/tags/tree` | **Keep as app-platform route for this phase.** Its nested JSON is currently produced by Swift `TagManagementService.tagTree()`; don't rebuild the tree independently in each caller. | Retain until the app exposes this same formatter through a generated service contract. |
| **imbib** — `GET /api/export?format=ris` | **Additive verb:** add `imbib-library-service_export-ris(ids: Vec<String>) -> String`, matching `imbib-library-service_export-bibtex(ids)` selection semantics and returning RIS text. | Format selection is domain export. Retire after byte-for-byte record coverage and caller conversion to the raw verb result. |
| **imprint** — `GET /api/documents` | **Additive DTO fields:** add `authors: Vec<String>`, `status: String`, `word_count: u32`, `last_modified: Option<String>`, and `created_at: String` to `DocumentSummary` returned by `imprint-manuscript-service_list-documents()`. | The active HTTP list includes these fields. Add them before migrating callers; compare all response fields before retiring. |
| **imprint** — `GET /api/documents/{id}` used by impart's `ArtifactResolver` | **Caller composition plus additive DTO fields:** compose `imprint-manuscript-service_get-document(id)` with `imprint-app-service_get-content(document_id)`; include route fields `authors`, `status`, `last_modified`, `created_at`, `linked_imbib_manuscript_id`, and `linked_imbib_library_id` in `DocumentSummary`. Derive `word_count` and `preview_text` from content; keep `version` optional because the route does not return it. | Move the resolver only after `DocumentArtifactData` fields match. |
| **imprint** — `POST /api/documents/{id}/update`, `/replace`, `/insert`, `/delete`; `PUT .../metadata` | **Keep these as platform routes for this phase; do not add parallel queue-only verbs.** `ImprintHTTPRouter` enqueues `DocumentOperation` in `DocumentRegistry` on `MainActor` and registers an `OperationTracker` ID. | Existing `imprint-app-service` edit verbs commit synchronously through callbacks; they do not enter `DocumentRegistry` or produce the route's `operationId`. A generated verb needs a native callback into that same registry/tracker before these routes can retire. |
| **imprint** — `POST /api/documents/{id}/insert-citation` | **Keep as a live-editor platform route.** Its caret position, open-editor requirement, and conflict response are tied to current editor state. | Do not convert to source mutation or infer a caret. Revisit only if the editor exposes an equivalent platform callback through the service backend. |
| **imprint** — comment list/create/update/delete and accept/reject routes | **Additive DTO/argument/verb changes:** extend `CommentRecord` with `parent_id`, `proposed_text`, and `author_agent_id`; change `imprint-app-service_list-comments(document_id, filter: Option<String>, author_agent_id: Option<String>)`; add those same comment fields to `imprint-app-service_create-comment`; add `imprint-app-service_accept-comment-suggestion(comment_id) -> SuggestionApplyResult` and `imprint-app-service_reject-comment-suggestion(comment_id) -> bool`. Keep `imprint-app-service_update-comment` for body and open/resolved only. | The HTTP contract supports threading, agent attribution, filtering and applying a suggestion. The current update verb explicitly refuses accepted/rejected status; do not map acceptance to status-only update. Migrate after parity. |
| **implore** — `GET /api/figures`, `GET /api/figures/{id}` | **Additive DTO fields:** add `figure_type`, dimensions, optional axis/color columns and title, timestamps, tags and folder ID to `FigureRecord`; retain optional `dataset_name` and `view_state` for richer hosts (the current HTTP formatter omits both); keep `implore-service_list-figures(dataset_id)` and `implore-service_get-figure(figure_id)`. | These are app-domain reads. Move the caller only after DTO parity, including absent/null values, is demonstrated. |
| **implore** — `GET /api/figures/{id}/export` | **Additive verb:** retain `implore-service_export-figure(figure_id, format)` and add `implore-service_export-figure-data(figure_id, format, width: Option<f64>, height: Option<f64>, scale: Option<f64>, view_state: Option<String>) -> FigureExport { path, sha256, mime_type, data: Vec<u8> }`. | The current verb returns a path; HTTP returns image bytes encoded in a JSON base64 envelope with metadata. Retain the route until generated-result callers handle matching PNG/SVG bytes. |
| **implore** — `POST /api/figures`, `PATCH /api/figures/{id}`, `DELETE /api/figures/{id}` | **Additive contract:** extend `implore-service_create-figure` with route width/height/view-state inputs; add `implore-service_update-figure(figure_id, dataset_id, plot_type, x, y, name, series, spec, svg, width, height, view_state)` and `implore-service_delete-figure(figure_id) -> bool`. Update must rerender/store the artifact; delete must remove exports/blob only when unreferenced, as the route does. | Current create lacks some REST configuration, and update/delete are absent. Retire only after matching cleanup and rerender behavior. |
| **implore** — `/api/rg/slice/png`, `/api/rg/cascade_plot`, `/api/plot/svg`, `/api/plot/histogram` | **Keep as viewer/rendering platform routes for this phase.** The ray-grid routes use live viewer options and raw image output; plot routes return raw SVG responses. | Preserve content type, bytes, and live viewer state. A future binary/render service contract can replace these as a separate capability. |
| **impart** — `GET /api/research/conversations`, `GET .../{id}` | **Additive DTO/argument changes:** add `participants`, `tags`, `parent_conversation_id`, and `last_activity_at` to `ConversationRecord`; change `impart-service_list-conversations(limit, include_archived, offset: Option<u32>, query: Option<String>)` to return `ConversationList { conversations, total, offset, limit, query }`; extend `impart-service_get-conversation(conversation_id)` with `messages` and `statistics`. | Existing list/get verbs omit route data and Counsel reads the old envelope. Convert Counsel to map the richer raw result and verify count/total/query semantics before removing either route. |
| **impart** — create/update, messages, branch, artifacts, decisions, archive routes | **Keep as platform routes for this phase; do not add parallel queue-only verbs.** `ImpartHTTPRouter` enqueues `ConversationOperation` into `ConversationRegistry` on `MainActor` and returns an accepted/queued response (create also returns its reserved conversation ID); generated `impart-service` mutations write immediately and have no registry callback. | Keep routes until `impart-service` can enqueue through that same UI registry and preserve each route's accepted response and reserved ID. The DTO/argument changes above apply to reads and remain needed separately. |
| **impart** — accounts, mailboxes, messages; status/logs; app-only manuscript/e-ink/revision/compile and viewer routes | **Keep as app-platform routes.** | These represent app-local UI, account, binary, compiler, hardware, or live-viewer capabilities rather than a shared domain verb in this proposal. `GET /api/status` and `GET /api/logs` remain transport diagnostics. |

### Migration order

1. Implement the delegated contract choices above in small packages; record any
   evidence-driven refinement in the plan session log.
2. Implement each approved contract in its app service and native backend while
   retaining the route. Add route-to-verb parity coverage for values, errors,
   queue IDs, and binary bytes where applicable.
3. Migrate the named Swift and Counsel callers to generated verbs. Keep private
   handlers still used by native callbacks.
4. Remove only the route registrations proven to have no remaining caller;
   retain the platform routes listed above. Update the P5b inventory with the
   verified result.
