# P5c retained-route contract proposal

**Proposal only — not approved.** P5b deliberately left richer REST contracts
in place. This proposes the smallest generated-verb additions that preserve
those capabilities, alongside routes that can move through caller composition
and routes that should remain app-platform APIs. Existing descriptors cited
below were checked in the service traits; proposed additions need Tom's review
before implementation. The current REST behavior remains authoritative until
that review and the migration proofs are complete.

| App / retained route | Proposed disposition and exact contract choice | Why / sequencing |
| --- | --- | --- |
| **imbib** — `GET /api/search`, `GET /api/papers/{citeKey}` | **Caller-only composition.** Keep `search-publications(query, limit)` for the list. For cite-key detail, call `search-publications` to find the ID, then `get-publication-detail(id)` and map the detail fields to the existing response. | Both verbs already exist; `PublicationDetailRecord.fields` carries BibTeX metadata. Convert the active Swift caller and impel consumer first, then remove these route arms. |
| **imbib** — `GET /api/search/external` | **Additive DTO field — Tom review:** add `identifier: Option<String>` to `ExternalPaper`, populated with the same importable identifier the HTTP candidate exposes, including candidates without DOI/arXiv/bibcode. Retain `search-sources(query, sources, limit)`. | `search-sources` already matches query/source/limit, but callers cannot safely reconstruct every candidate's import key from current fields. Migrate caller, prove identifier parity, then retire. |
| **imbib** — `POST /api/papers/add`, `/api/papers/resolve` | **Additive verbs — Tom review:** `import-identifiers(identifiers: Vec<String>, library_id: Option<String>, collection_id: Option<String>, download_pdfs: bool) -> IdentifierImportResult` with `added`, `duplicates`, and `failed` per-paper outcomes; and `resolve-citation(query: Option<String>, bibtex: Option<String>, citation: Option<CitationInput>, library_id: Option<String>, download_pdfs: bool) -> CitationResolution { via, paper?, candidates?, reason? }`. `CitationInput` carries `authors`, `title`, `year`, `journal`, `volume`, `pages`, `doi`, `arxiv`, `bibcode`, `raw_bibtex`, `free_text`, and `preferred_database`. | `import-papers(papers, library_id)` only imports BibTeX and returns aggregate counts; `resolve-identifier(identifier, download_pdfs)` cannot accept the route's free-text, BibTeX, or structured citation forms and ranked candidates. Keep both routes until the new results reproduce per-paper outcomes and the caller has moved. |
| **imbib** — `GET /api/libraries`, `GET /api/collections` | **Additive DTO/argument changes — Tom review:** add `collection_count` and `can_edit` to `LibraryRecord`; make `list-collections(library_id: Option<String>)` list across libraries when omitted, retaining each row's `library_id`. | Listing collections per existing `list-libraries` result is caller-composable, but HTTP callers also need sharing/editability and collection counts. Add fields and optional filter, migrate callers, then remove routes. |
| **imbib** — `GET /api/export?format=ris` | **Additive verb — Tom review:** `export-ris(ids: Vec<String>) -> String`, matching `export-bibtex` selection semantics and returning RIS text. | Format selection is domain export, not platform state. Route can retire after byte-for-byte record coverage and caller conversion to the raw verb result. |
| **imprint** — `GET /api/documents` | **Additive DTO fields — Tom review:** add `authors: Vec<String>`, `status: String`, `word_count: u32`, `last_modified: Option<String>`, and `created_at: String` to `DocumentSummary`; keep `list-documents()`. | The active HTTP list includes these fields. Add them before migrating callers; compare all response fields before retiring. |
| **imprint** — `GET /api/documents/{id}` used by impart's `ArtifactResolver` | **Caller-only composition plus additive DTO fields — Tom review:** compose `get-document(id)` with `get-content(document_id)`; include the route's `authors`, `status`, `last_modified`, `created_at`, `linked_imbib_manuscript_id`, and `linked_imbib_library_id` in `DocumentSummary`. Derive `word_count` and `preview_text` from the composed content; keep `version` optional because the route does not return it. | These reads are already verbs. Move the resolver and verify `DocumentArtifactData` equivalence before removing the HTTP read. |
| **imprint** — `POST /api/documents/{id}/update`, `/replace`, `/insert`, `/delete`; `PUT .../metadata` | **Additive queued-operation verbs — Tom review:** `queue-document-update(document_id, source: Option<String>, title: Option<String>)`, `queue-document-replace(document_id, search, replacement, all: bool)`, `queue-document-insert(document_id, position: u32, text)`, `queue-document-delete(document_id, start: u32, end: u32)`, `queue-document-metadata(document_id, title: Option<String>, authors: Option<Vec<String>>)`; each returns `QueuedEditorOperation { operation_id }`. Preserve the current queue acknowledgement and first-match behavior when `all == false`. | The existing native edits commit synchronously; replacing the route with them changes acknowledgment and ordering. Keep route handlers until the app backend queues the same editor operations and callers can observe the same operation IDs. |
| **imprint** — `POST /api/documents/{id}/insert-citation` | **Keep as a live-editor platform route.** Its caret position, open-editor requirement, and conflict response are tied to current editor state. | Do not convert to source mutation or infer a caret. Revisit only if the editor exposes an equivalent platform callback through the service backend. |
| **imprint** — comment list/create/update/delete and accept/reject routes | **Additive DTO/argument/verb changes — Tom review:** extend `CommentRecord` with `parent_id`, `proposed_text`, and `author_agent_id`; change to `list-comments(document_id, filter: Option<String>, author_agent_id: Option<String>)`; add `parent_id`, `proposed_text`, and `author_agent_id` to `create-comment`; add `accept-comment-suggestion(comment_id) -> SuggestionApplyResult` and `reject-comment-suggestion(comment_id) -> bool`. Keep `update-comment` for body and open/resolved only. | The HTTP contract supports threading, agent attribution, filtering and an apply-suggestion action. The current verb explicitly refuses accepted/rejected status; preserve that distinction and do not map acceptance to status-only update. Migrate after the verbs can reproduce each route result. |
| **implore** — `GET /api/figures`, `GET /api/figures/{id}` | **Additive DTO fields — Tom review:** add `figure_type`, `dataset_name`, `modified_at`, and `view_state` to `FigureRecord`; keep `list-figures(dataset_id)` and `get-figure(figure_id)`. | These are app-domain reads. Move the caller only after DTO parity, including absent/null values, is demonstrated. |
| **implore** — `GET /api/figures/{id}/export` | **Additive verb — Tom review:** retain `export-figure(figure_id, format)` and add `export-figure-data(figure_id, format, width: Option<u32>, height: Option<u32>, scale: Option<f64>, view_state: Option<String>) -> FigureExport` where `FigureExport` contains `path`, `sha256`, `mime_type`, and `data: Vec<u8>`. | The current verb returns a path; the HTTP caller gets image bytes and metadata. Keep the raw HTTP response until the app caller handles the generated result and PNG/SVG bytes match. |
| **implore** — `POST /api/figures`, `PATCH /api/figures/{id}`, `DELETE /api/figures/{id}` | **Additive argument/verbs — Tom review:** extend `create-figure` with the route's width, height, and view-state inputs; add `update-figure(figure_id, dataset_id, plot_type, x, y, name, series, spec, svg, width, height, view_state)` and `delete-figure(figure_id) -> bool`. `update-figure` must re-render and update the stored artifact; delete must remove exports/blob only when unreferenced, as the route does. | The current create verb does not cover the full REST figure/view configuration, and update/delete are absent. Retire each write route only after matching its artifact cleanup and rerender behavior. |
| **implore** — `/api/rg/slice/png`, `/api/rg/cascade_plot`, `/api/plot/svg`, `/api/plot/histogram` | **Keep as viewer/rendering platform routes for this phase.** The ray-grid routes use live viewer options and raw image output; plot routes return raw SVG responses. | Preserve content type, bytes, and live viewer state. A future binary/render service contract can replace these as a separate approved capability. |
| **impart** — `GET /api/research/conversations`, `GET .../{id}` | **Additive DTO/argument changes — Tom review:** add `participants`, `tags`, `parent_conversation_id`, and `last_activity_at` to `ConversationRecord`; change `list-conversations(limit, include_archived, offset: Option<u32>, query: Option<String>)` to return `ConversationList { conversations, total, offset, limit, query }`; extend `get-conversation(conversation_id)` result with `messages` and `statistics`. | Existing list/get verbs omit route data and Counsel reads the old envelope. Convert Counsel to map the richer raw result and verify count/total/query semantics before removing either route. |
| **impart** — create/update, messages, branch, artifacts, decisions, archive routes | **Additive queued-operation verbs — Tom review:** add `queue-create-conversation(title: String, participants: Vec<String>)`, `queue-update-conversation(conversation_id: String, title: Option<String>, summary: Option<String>, tags: Option<Vec<String>>)`, `queue-add-message(conversation_id: String, sender_role: String, sender_id: String, content: String, causation_id: Option<String>)`, `queue-branch-conversation(conversation_id: String, from_message_id: String, title: String)`, `queue-record-artifact(conversation_id: String, uri: String, type: String, display_name: Option<String>)`, `queue-record-decision(conversation_id: String, description: String, rationale: String)`, and `queue-archive-conversation(conversation_id: String)`. Each returns `QueuedResearchOperation { operation_id: String }`. | Keeping the current immediate `create-conversation`, `add-message`, and related verbs intact avoids changing their established signatures and synchronous result meaning. Move callers and remove routes only after the same UI queue acknowledgement is observable through these additions. Keep app UI queueing as the implementation backend. |
| **impart** — accounts, mailboxes, messages; status/logs; app-only manuscript/e-ink/revision/compile and viewer routes | **Keep as app-platform routes.** | These represent app-local UI, account, binary, compiler, hardware, or live-viewer capabilities rather than a shared domain verb in this proposal. `GET /api/status` and `GET /api/logs` remain transport diagnostics. |

### Migration order

1. Approve or revise the additive DTO, argument, result, and queued-operation
   choices above; do not change public signatures before that decision.
2. Implement each approved contract in its app service and native backend while
   retaining the route. Add route-to-verb parity coverage for values, errors,
   queue IDs, and binary bytes where applicable.
3. Migrate the named Swift and Counsel callers to generated verbs. Keep private
   handlers still used by native callbacks.
4. Remove only the route registrations proven to have no remaining caller;
   retain the platform routes listed above. Update the P5b inventory with the
   verified result.
